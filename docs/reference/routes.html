Reference

Addresses in the web interface

Every page of EiN's web interface has an address of its own, and most of what a page shows, such as the tab, the filters, the year or the part of the map, is written into that address. This page lists the addresses and their parameters, so you can bookmark a view, send someone a link to it, or type one in. It is for anyone who uses EiN in a browser, and for administrators who link to EiN from elsewhere.

How an address is made

An address is the place EiN is reached at, then a path, then sometimes a query:

http://ein.local:8080/people/helen-okafor?tab=faces
└──── where EiN is ──┘└────── path ──────┘└─ query ─┘
  • The path says which page: /people/helen-okafor is Helen Okafor's page.
  • The query, after ?, says how the page looks: tab=faces opens it on Faces. Several parameters are joined with &.
  • A part that holds a path in the tree, such as an album's, is URL-encoded: / becomes %2F and a space %20. EiN writes these addresses itself when you move around; you only meet the encoding when you type one by hand.

Copy the address from the browser's address bar to share or bookmark what you see. Someone who opens it sees the same page, as far as their own permissions let them.

The pages come from EiN itself and from its modules. The lists below are those of an installation with the Archive, the Assistant and the media service. A module that is not installed brings none of its addresses, and opening one shows Nothing here.

Pages, dialogs, the side panel and full screen

The same address can be shown four ways. Which one depends on how you open it, not on the address:

Shown as How you get there Is it in the address bar?
A page The sidebar, a link, or typing the address Yes, as the path
A dialog over the page Entries of the top bar's Create New menu, About EiN in the account menu No
The side panel beside the page The top bar's Chat button No
Full screen A picture, video or recording opened from a grid, a memory on the home page Yes, as ?fullscreen=

Create New → Person opens /people/new in a dialog; typing /people/new into the address bar opens the same form as a page. In the same way, /chat is the side panel from the top bar and a full page from the sidebar. On a phone, what would open in the side panel opens in a dialog instead. Finding your way around shows each of these.

Full screen is the one kind that lives in the address. When you open a picture from an album, the address keeps the album and adds the picture:

/albums/%2Farchive%2Falbums%2FMalpas%201979?fullscreen=%2Fmedia%2F%252Farchive%252F…

Back closes the picture and leaves you on the album, and a reload or a shared link opens the album with the picture over it. Opened by its own address, /media/<path>, the picture is the page.

"Everyone who can browse" means signed-in users, and also visitors who have not signed in when the administrator turns on CFG_GUEST_BROWSING. A page marked "Signed in" always asks a visitor to sign in first. What each person then sees on a page follows the permissions on the nodes behind it; see Permissions in depth.

The Archive's pages

Addresses with <name> take the name of the node in the tree, which is the person's, place's or device's name in lower case with hyphens: Helen Okafor is /people/helen-okafor. Addresses with <path> take the node's whole path, URL-encoded.

Parameters

A parameter that is missing, or holds a value the page does not know, is ignored: the page opens as it would without it. You never get an error for a mistyped parameter.

Search and Media

Search and Media keep their whole search in the address, so a search can be linked to and survives a reload. The parameters are named after the flags of the search command.

Parameter What it holds Example
q The words searched for q=sailing
kind Kinds, separated by commas: photo, video, audio, document, person, location, album, device, track kind=photo,video
tag Labels, separated by commas tag=beach
subject A person, location or device that must be in it, as <kind>:<name> or a path; repeat it for several, all of which must be there subject=person:helen-okafor
subject-name Every subject of a kind whose name matches the words, as <kind>:<words>; repeatable subject-name=person:Wrenfield
from, to The first and last year, both included from=1975&to=1985
bbox A rectangle on the map: north, south, east, west bbox=50.3,50.2,-5.0,-5.1
circle A circle on the map: latitude, longitude, radius in metres circle=50.263,-5.051,2000
poly A polygon: at least three latitude,longitude pairs separated by ; poly=50.3,-5.1;50.3,-5.0;50.2,-5.0
under Only what one album or folder holds, by path under=/archive/albums/Malpas 1979
like Pictures that look like this one, by path like=/archive/…/IMG_0412.jpg
sort score, time (oldest first), -time (newest first) or name sort=-time

For example, every picture and video of Helen Okafor from the 1980s, newest first:

/media?kind=photo,video&subject=person:helen-okafor&from=1980&to=1989&sort=-time

Only one of bbox, circle and poly applies. Search with no parameters shows its landing page rather than searching for everything.

Map

The map keeps where you look, the layers and the filters in the address. What is at its default is left out, so a plain /map stays plain.

Parameter What it holds Default
c The centre, as latitude,longitude
z The zoom level
layers Layers shown, separated by commas: media, locations, tracks; or none All three
from, to The first and last year No limit
base The background: Map, Dark map or Satellite Map
q Words to search for
person, location, tag Only what has this person, location or label 
/map?c=50.26300,-5.05100&z=13&layers=media,tracks&from=1979&to=1979&base=Satellite

Signing in and share links

The return after signing in

A visitor who opens a page they must sign in for is sent to the sign-in page, with the address they asked for in next:

/login?next=%2Fpeople%2Fhelen-okafor%3Ftab%3Dfaces

After signing in they land on that page. next only leads to a page on the same EiN; anything else leads to Home. Someone already signed in who opens /login goes straight on to next, or to Home.

Share links

A share link has the form /s/<token>, for example http://ein.local:8080/s/ followed by a long string of letters and digits. You make one with Share in the interface, see Sharing, or with share-link create in the terminal.

Opening it shows Opening what was shared with you… and then the page of what was shared, such as the album's address. Where visitors may not browse, the visitor stays on what the link opens: other pages ask them to sign in. A link that has expired or been turned off shows This link no longer works with a Sign in button.

When an address does not open

What you see What it means What to do
Nothing here and "There is no page at …" No page has that path: a typing mistake, or a page of a module that is not installed Check the address; Go back or Go home
The sign-in page The page is for signed-in users, or visitors may not browse Sign in; you go on to the page afterwards
This page did not load The page's code could not be fetched, often because EiN was updated while the tab was open Choose Reload
Something broke on this page The page failed while drawing; the error is shown below the message Choose Reload; if it keeps happening, see Troubleshooting
This link no longer works A share link that expired or was turned off Ask for a new link, or sign in

In a dialog or the side panel the same messages appear smaller, with Close in place of Go home.

After an administrator installs or updates a module, its pages reach the browser once EiN has rebuilt them with ui-build, which it does when it starts. An open tab picks them up when you reload it.

Other addresses the server answers

Besides the pages, EiN's web server answers a few addresses that programs use rather than people. You meet them in links to files, in scripts, and in a reverse proxy's configuration (Ports, HTTPS and remote access).

Address Method What it does
/file/<path> GET, HEAD The bytes of a file in the tree, read with the permissions of whoever asks
/file/<path> PUT Stores the body at exactly that path, creating or replacing the file
/file/<directory>/?name=<name> POST Stores an upload under a name nothing in the directory has yet: name, else name (2), name (3) and so on
/archive POST Collects a selection of files for a download as one zip
/archive/<token> GET Downloads that zip
/log/<path> POST Adds JSON entries to a log node
/track/<path> POST Adds GPS points to a track node, see Devices and GPS tracks
/__shell The connection the web interface talks to EiN over; a proxy must pass it on as a WebSocket

Any other path that is not a file of the web interface returns the interface itself, which then shows the page or Nothing here. A visitor who is not signed in where visitors may not browse gets sign in first from /file/ and /archive/.
