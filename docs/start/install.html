Getting started

Install EiN

This page takes you from a Linux machine to an EiN you can sign in to: what the machine needs, the one command that installs EiN, what you see while it runs, and what to do first once it is up. It is the quick path for trying EiN on your own machine. Installing in detail covers everything else.

What you need

EiN runs as a few containers on one Linux machine. The installer downloads their images, which GitHub builds from the newest source: there are no releases. It needs no root, but the tools it uses must be installed first.

What the machine needs depends on whether you install EiN on its own (EiN Core) or with the media service, which the Archive needs to make thumbnails, find faces, read text and make pictures searchable:

EiN Core With the media service (--ems)
System Linux on x86-64 Linux on x86-64
Container engine podman, run as your own user (rootless), with podman compose; or Docker with its compose plugin the same
Tools git and curl the same
Processor 2 cores 4 cores; 6 or more recommended
Memory 4 GB 16 GB; 32 GB recommended
Free disk 10 GB, plus your files about 100 GB, plus your files
Graphics card not used optional: NVIDIA, 16 GB recommended, 8 and 12 GB work

Cores are counted as physical cores, not threads. The language model for the assistant (--llm) takes several GB more, on the graphics card or in memory, and about 6 GB more disk for its file. With 16 GB of memory, leave it out or use a hosted model instead; The language model explains both.

A few more things to know before you start:

  • No macOS, Windows or ARM. The installer stops at once on anything but Linux on x86-64, a Raspberry Pi included.
  • Internet access. The install downloads EiN's images from GitHub's registry, ghcr.io. At its first start EiN downloads the modules you named from GitHub, and the language model downloads its model from Hugging Face.
  • Docker needs your user to have access to its daemon, usually by being in the docker group. The installer does not check this.
  • A graphics card is optional. Without one everything works, only slower. Only NVIDIA cards are used, with driver 610 or newer to encode video on the card. The graphics card has the setup.
  • A current browser that shows AVIF and plays AV1 video: Chrome, Edge or Firefox, or Safari 17 and newer on an Apple device that decodes AV1 (M3, A17 Pro or later).

On Ubuntu 24.04, for example, this installs the tools for the podman route:

# on the machine that will run EiN
sudo apt install podman podman-compose git curl

Note

When both podman and Docker are installed, EiN uses podman. To use Docker, add --engine docker after bash -s -- in the install command, as in curl -fsSL https://einhq.eu/install.sh | bash -s -- --engine docker. setup.sh keeps the engine in .env, and every later run uses it. The installer's own checks still look at podman when it is there. Installing in detail explains what happens when the two are mixed.

Choose what to install

The installer asks how to install EiN, checks the machine against what you chose, and installs nothing when it falls short.

Answer its questions. Run at a terminal, the installer asks one thing at a time, each with its default in brackets: Enter keeps the default.

# on the machine that will run EiN, as your own user
curl -fsSL https://einhq.eu/install.sh | bash
Installing EiN. Enter takes the default in brackets; any of these can be changed later.

Where EiN goes [/home/anna/ein]:
The folder for your files, the database among them [/home/anna/ein/data]: /mnt/photos/ein
The admin account's password, 8 characters or more [Enter: one is made for you]:
EiN's official modules: y installs one, Enter leaves it out. Any can be added later.
  archive        photos, videos and documents, people and places; with the media service, ~30 GB [y/N] y
  assistant      a chat that answers questions; with a language model here, about 6 GB [y/N] y
  automation     sensors, plugs and lights, and automations; with an MQTT broker [y/N]
  album-folders  the Archive's albums as folders on disk; brings the Archive [y/N]
  recipes        recipes with ingredients, steps and pictures; with the media service [y/N]
  todo           todo lists, personal or shared within a group [y/N]
The web interface's port [8080]:
SSH and SFTP's port [2222]:
Can other machines reach EiN? n keeps it to this machine, behind an HTTPS proxy of your own [Y/n]

EiN is to be installed with:
  folder          /home/anna/ein
  your files      /mnt/photos/ein
  admin password  one made for you, shown at the end
  modules         archive assistant, with the media service, the language model
  web interface   port 8080, every address of this machine
  SSH and SFTP    port 2222
Install? [Y/n]
Question Default What it decides
Where EiN goes ~/ein The folder for setup.sh, the compose files and .env.
The folder for your files ~/ein/data Your originals, their thumbnails, the installed modules and the database. Put it on a disk with room for your originals, in a folder your user can write to. It is chosen once: later runs keep it.
The admin account's password one made for you The admin account's first password: 8 characters or more, without ' or \. It is not shown as you type, and asked twice. Enter alone makes one, which is shown at the end.
The official modules none Each module on a line of its own: y and Enter installs it, Enter alone leaves it out. Leave them all out for EiN Core: EiN and its database, the tree, the Web UI, the shell, SSH and SFTP.
The web interface's port 8080, or the next free one The port of the machine the Web UI is reached on. When something else has 8080, the question offers the next free port and says (8080 is taken).
SSH and SFTP's port 2222, or the next free one The port of the machine SSH and SFTP are reached on.
Can other machines reach EiN yes n keeps EiN to the machine itself, for an HTTPS proxy of your own on the same machine; see Ports, HTTPS and remote access.

Then it shows what the answers add up to and asks Install? [Y/n]. Enter installs; n stops with Nothing was installed.

Name the modules. The modules you name after bash -s -- are installed without the question about modules; the installer still asks the others. For EiN Archive, the full Archive installation, that is the Archive and the assistant:

# on the machine that will run EiN, as your own user
curl -fsSL https://einhq.eu/install.sh | bash -s -- archive assistant

Take the defaults. --yes, or -y, asks nothing: EiN goes in ~/ein, your files in ~/ein/data, a password is made for the admin, the ports are 8080 and 2222, or the next free ones, on every address of the machine, and the modules are those you name. Run without a terminal, such as from a script, the installer does the same and says No terminal to ask on: installing with the defaults and the options given, as --yes does.

# on the machine that will run EiN, as your own user
curl -fsSL https://einhq.eu/install.sh | bash -s -- --yes archive assistant

A module's name brings the services it needs:

Name What it installs
archive The Archive, with the media service (--ems): every media tool and model, in an image of about 30 GB.
assistant The assistant, with the language model it answers with (--llm), Qwen3.5-4B in llama.cpp.
automation Automation, with an MQTT broker for its devices (--mqtt), on port 1883 of the machine.
album-folders Album folders, with the Archive it needs and the media service.
recipes Recipes, with the media service, which makes the pictures' thumbnails.
todo Todo lists.

Run again where EiN is installed, the installer asks nothing: it updates EiN with the settings it has (Updating).

An option answers its question, which the installer then does not ask:

Option Answers
--home <folder> Where EiN goes.
--data <folder> The folder for your files.
A module's name, or --module <name> Which modules to install.
--http-port <port>, --ssh-port <port> The ports.
--bind <address> Whether other machines reach EiN: 0.0.0.0 for every address of the machine, 127.0.0.1 for it alone.

The admin password is not an option, so that it stays off the command line: the installer takes it from INITIAL_ADMIN_PASSWORD in its environment instead of asking. Installing in detail shows how.

Everything after bash -s -- other than a module's name and --home, --yes and --check is passed on to ~/ein/setup.sh, EiN's own setup script, and the names become its options: archive is --ems --module archive. Its options can be given the same way:

Option What it adds
--ems The media service: every media tool and model, in an image of about 30 GB. It uses the graphics card when the first install found one ready for containers.
--llm The language model the assistant answers with, Qwen3.5-4B in llama.cpp.
--module <name> A module, such as archive or assistant, which EiN installs at its start with the modules it needs, without the services it needs. Give it once for each module.
--mqtt An MQTT broker for the Automation module's devices, on port 1883 of the machine.
--no-ems, --no-llm Leave the media service or the model out again on a later run. Its data stays.

Note

The Archive module needs the media service. Installed with --module archive but without --ems, it still installs: the installer's archive line says low, and setup.sh ends with The Archive module needs the media service, which is not installed here: ./setup.sh --ems adds it. Nothing you upload then gets thumbnails, dates, faces or searchable text: that work waits until the media service is there. Modules lists what each module needs.

Check the machine without installing

--check runs the checks for the options you give and stops, asking nothing:

# on the machine that will run EiN
curl -fsSL https://einhq.eu/install.sh | bash -s -- --check archive assistant

You can read the installer before you run it: it is at einhq.eu/install.sh, and its source is on GitHub.

Choose where your files go

EiN goes in ~/ein, and your files in ~/ein/data, unless you answer the questions with other folders or name them with --home and --data. The folder for your files holds your originals, so put it on a disk with room for them, in a folder your user can write to:

# on the machine that will run EiN, as your own user
curl -fsSL https://einhq.eu/install.sh | bash -s -- --data /mnt/photos/ein archive assistant

The folder for your files is chosen at the first install, when ~/ein/.env is written. Later runs keep the folder named there, and setup.sh refuses another --data.

Run the installer

  1. Open a terminal on the machine as your own user. Do not use sudo or a root shell: the installer and EiN are meant to run as your own user.
  2. Paste one of the install commands above and press Enter.
  3. Read the report. Each line is one check, its result, and why:
EiN: checking this machine against the system requirements

  system           ok       Linux on x86-64
  podman           ok       5.4.2, rootless
  compose          ok       podman compose, with podman-compose
  git              ok
  curl             ok
  processor        ok       8 cores
  memory           ok       31 GB
  disk             ok       870 GB free under /home/anna/ein/data (not made yet; measured on /home/anna), plus room for your own files
  graphics         ok       NVIDIA GeForce RTX 4070, 12282 MB, driver 610.31
  card memory      low      12282 MB: works; 16 GB is recommended, room for the media models and the assistant side by side
  container GPU    ok       nvidia-container-toolkit 1.18.1, CDI spec in /var/run/cdi

This machine can run EiN; 1 item(s) are below what is recommended.

The graphics lines appear only with --ems or --llm, and the thresholds for processor, memory and disk are the higher ones only with --ems. On a terminal the results are coloured:

Result Colour What it means
ok green The machine meets it.
low yellow Below what is recommended. The install goes on. Every graphics line is at most low: without a usable card, the media service and the model run on the processor.
missing red A requirement is not met. The reason says what to install or how much is needed.

The last line is the verdict:

Verdict What happens
<n> requirement(s) not met, so nothing was installed. The installer stops before it fetches anything, and your machine is as it was. Fix what the missing lines name and run the command again.
This machine can run EiN; <n> item(s) are below what is recommended. The install goes on. The low lines tell you what would make EiN faster or roomier.
This machine meets the recommended requirements. The install goes on.

The disk check measures the free space where your files go. The images and the database are kept in the container engine's own storage (for rootless podman, usually under ~/.local/share/containers), which is often the same disk but need not be: that disk needs the room too.

What the installer does

The installer asks its questions first, at a first install, and then checks the machine against what you chose. Once the checks pass, it:

  1. Fetches ein/deploy into ~/ein, or updates it when it is there already, and runs ~/ein/setup.sh with your options.
  2. setup.sh writes ~/ein/.env the first time: your options, the folder for your files, the ports, the passwords it makes for the database and the media service, and the admin account's first password, the one you chose or one it makes.
  3. It downloads the images of EiN and its database, and of the media service and the model when you chose them. Their sources, for the media service and the model, it fetches into ~/ein/src.
  4. From an organisation of your own (--source), it fetches the sources into ~/ein/src instead and builds the images on your machine; Where the sources come from explains it.
  5. It starts everything with podman compose or docker compose, and waits for EiN to answer.
  6. At its first start, EiN sets up its database, makes the admin account, downloads the modules you named and the modules they need, sets them up, starts its services, and gives admin the password INITIAL_ADMIN_PASSWORD in .env.
  7. setup.sh prints the address of EiN. A password it made for the admin it prints too, and again at the end of every run until you delete its line from .env. A password you chose it removes from .env once EiN has taken it, and says Sign in as admin with the password you chose.
  8. It makes EiN start again when the machine does, where your user may: under podman it turns on podman-restart.service for your user and lets your user's services run without a login. What it may not do, it prints as commands for you to run, such as sudo loginctl enable-linger anna.
  9. It lists the modules installed, each with its version and the release it was installed at, and below them any line EiN's start logged about a module it could not install or run.

How long it takes

Most of the time goes into downloading the images, and how long that takes depends on your connection. EiN Core is a few hundred MB. With the media service, its image of about 30 GB takes by far the longest. The container engine prints its own progress as it goes. Built from your own source instead, the media service's image takes about an hour more.

After == Starting EiN, setup.sh prints Waiting for EiN to answer at … and then, every 10 seconds, EiN's newest log line when it has changed. The first start takes longer, as EiN also downloads the modules you named. It waits up to 10 minutes, and stops sooner when EiN's container stops or keeps restarting.

With the media service and the model, two parts are still getting ready when the password appears. The media service loads its models for a few minutes after it starts; until then the Status page's health check for ems says http://ems:8181 is not answering; work that needs it waits, and the work resumes by itself. The language model downloads its model the first time it starts, so the assistant may not answer for a while.

What is where

Where What it holds
~/ein setup.sh, the compose files, the sources under src/, and .env
~/ein/.env your options and the passwords made at the install, kept nowhere else
~/ein/data, or the folder you chose your originals, the thumbnails and other renditions, scratch space, the language model and the installed modules
~/ein/data/db the database: every name, folder, album, person, setting and account

Keep .env safe. EiN has no backup command; Your data explains what to copy and why the database and the data folder belong together.

Sign in

  1. Open the address setup.sh printed, such as http://ein:8080/, in a browser. On the machine itself, http://localhost:8080/ works too. If another computer cannot find the machine by that name, use its address instead, such as http://ein.local:8080/ or http://192.168.1.20:8080/.
  2. In Username or e-mail, type admin.
  3. In Password, type the password you chose at the install, or paste the one setup.sh printed, and click Sign in.

You land on the home page, Welcome. What it shows comes from the modules: with the Archive it fills as pictures come in, and on EiN Core alone it stays empty. There is no setup wizard: First steps walks you from here to a family using it.

EiN listens on the ports you chose, 8080 for the web and 2222 for SSH and SFTP unless you chose others, on every address of the machine unless you kept it to the machine itself, over plain HTTP. That is fine at home. Before you make EiN reachable from outside your home, read Ports, HTTPS and remote access. When something else on the machine already uses 8080 or 2222, setup.sh gives EiN the next free port instead, says so (Port 8080 is taken on this machine: EiN uses 8081 instead (EIN_HTTP_PORT in .env)), keeps it in .env, and prints the address with it.

Change the admin password straight away

Do this before anything else when setup.sh made the password:

  • The password is in ~/ein/.env, as INITIAL_ADMIN_PASSWORD, readable by anyone who can read that file, and setup.sh prints it at the end of every run while the line is there.
  • Once you have changed it, delete that line from .env. Changing the line does not change the password: EiN reads it only at its first start.
  • A password you chose at the install is not kept there: setup.sh removes it from .env once EiN has taken it, so there is nothing to delete, and you need not change it.
  • EiN has no way to recover a lost administrator password. Only another administrator can set a new one, and a fresh install has no other.

In the Web UI

  1. Click your picture at the top right to open the account menu, and choose Profile.
  2. Open the Security tab.
  3. In Current password, enter the admin's password, the one setup.sh printed.
  4. Enter your own password in New password, and again in Confirm new password.
  5. Click Update password. Password updated appears beside the button.

In the terminal

Open the terminal with the terminal button in the top bar, or Alt+T, and run:

# in EiN's terminal
user passwd admin

It asks Password:, sets what you type, and answers Password updated successfully. It asks only once, so type carefully. The name is required: user passwd on its own answers user passwd: missing username. The reference lists its options.

Your profile, favourites and trash has more on the profile, and Accounts and groups on making accounts for your family.

Add parts later

Everything the Archive command installs can be added to EiN Core afterwards. Run the installer again with a module's name, such as curl -fsSL https://einhq.eu/install.sh | bash -s -- archive, or setup.sh in ~/ein with the option:

# on the machine EiN runs on
~/ein/setup.sh --ems              # the media service
~/ein/setup.sh --llm              # the assistant's language model
~/ein/setup.sh --mqtt             # an MQTT broker, for the Automation module's devices
~/ein/setup.sh --module archive   # a module, with the modules it needs
  • An option is kept in .env once given, so a later run without it keeps it. Give each option only when you add it.
  • Every run of setup.sh is also an update: it brings ~/ein itself up to date, fetches the newest sources of what is installed, builds again and restarts EiN, which is down while it starts. Updating has the details.
  • A module given with --module is installed by EiN at its next start, which that same run brings about.
  • --no-ems, --no-llm and --no-mqtt take the media service, the model or the broker out again. Their data stays.

Modules can also be installed without a restart. In the Web UI, open Settings → Modules, click the Published modules button beside the filter, and click Install on the module. In the terminal, mod install archive does the same (reference). Modules covers updating and removing them, and why a module you remove in Settings → Modules comes back at the next start while EIN_MODULES in .env still names it.

Instead of --llm, the assistant can use a hosted model, set in ~/ein/.env: see The language model.

When something goes differently

The commands here are written for podman. With Docker, write docker compose where they say podman compose.

What you see What to do
<n> requirement(s) not met, so nothing was installed. Nothing was changed. Install or free what the missing lines name, and run the command again.
The podman line says low and run as root here: run the installer, and EiN, as your own user You ran the installer as root. Run it again as your own user, without sudo.
The compose line says missing and install podman-compose, which 'podman compose' runs Install podman-compose, or for Docker its compose plugin, and run the command again.
A line about an external compose provider each time podman compose runs podman's own notice that podman compose runs podman-compose. It is not an error.
setup.sh: EiN stopped before it answered; its log is above: podman compose logs core EiN's container stopped, or restarted three times. The last lines of its log are printed above the message; they name what went wrong. See Troubleshooting.
setup.sh: EiN did not answer at http://127.0.0.1:8080/ in 10 minutes: podman compose logs core Look at what EiN is doing with cd ~/ein && podman compose logs core. A first start that downloads modules over a slow connection can take this long; podman compose ps shows whether it still runs.
Starting fails with unresolvable CDI devices nvidia.com/gpu=all The container engine cannot hand the graphics card to the containers. podman before 5, such as 4.9.3 on Ubuntu 24.04, needs a fix once per machine, which the installer's container GPU line names: see The graphics card.
No Sign in as admin line at the end .env has no INITIAL_ADMIN_PASSWORD line: you chose the password at the install, and setup.sh removed it once EiN had taken it; you deleted it; or .env was written before setup.sh kept the password there. In the last case a new EiN printed a random password to its log, below. When nothing is there, the database was there from an earlier install, so the admin already had a password, or the containers have been made again since. See Troubleshooting.
some modules could not be installed or replaced; continuing boot in the log EiN could not download a module, often for want of a connection to GitHub, or found no release of an installed one that it can run. The mod install: lines at the end of setup.sh's output say which and why. Install or update it from Settings → Modules once EiN is up.
The address does not open on another computer Use the machine's IP address instead of its name, and open ports 8080 and 2222 in the machine's firewall if it has one. See Ports, HTTPS and remote access.
EiN does not start again when the machine does until this has run: at the end setup.sh could not turn on what starts EiN at boot, such as lingering for your user. Run the commands listed below the line; until then, start EiN after a reboot with cd ~/ein && podman compose up -d. Installing in detail explains.
Uploads in the Archive get no thumbnails The media service is not installed, or is not answering yet. Without it, the installer's archive line says low and setup.sh ends with The Archive module needs the media service, which is not installed here: ./setup.sh --ems adds it. Add it with ~/ein/setup.sh --ems, or see The media service.

To find a random admin password in the log, as long as the containers have not been made again since:

# on the machine EiN runs on
cd ~/ein && podman compose logs core | grep 'Admin password set to'
