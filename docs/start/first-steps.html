Getting started

First steps

This page is for the administrator who has just installed EiN and is setting it up for a family. It goes from the first sign-in to the family using it, one short step at a time, and links each step to the page that covers it in full.

Take the steps in order. Some of them depend on an earlier one: the sharing defaults in step 4, for example, apply to albums made after you set them, so set them before the first import.

  1. Sign in and change the admin password
  2. Check the dashboard
  3. Install the modules you want
  4. Decide who sees what
  5. Create accounts for the family
  6. Import the first photos
  7. Share an album
  8. Let the family sign in
  9. Keep EiN running

Commands on this page are written for podman. With Docker, write docker compose where the page says podman compose.

Sign in and change the admin password

At its end the install printed the address and the administrator's password:

EiN is up at http://ein.local:8080/
Sign in as admin with the password 0b6f2c1e-8d4a-4c7e-9a51-2e7d3f6b9c40, and change it: it is shown this once.
  1. Open the address in a browser. If your computer cannot find that name, use the machine's IP address instead, such as http://192.168.1.20:8080/.
  2. Enter admin under Username or e-mail, the printed password under Password, and choose Sign in. EiN opens on Home, titled Welcome.
  3. Open the account menu under your picture at the top right, choose Profile, then the Security tab.
  4. Fill in Current password, New password and Confirm new password, and choose Update password. EiN answers Password updated.

Install EiN shows the form.

You can change it in EiN's terminal instead. Open the terminal with the top bar's terminal button or Alt+T, and run:

# in EiN's terminal
user passwd admin

It asks for the new password after Password:. The reference lists its options.

If the install's output is gone, the password is still in the container's log:

# on the machine EiN runs on, in ~/ein
podman compose logs ein | grep 'Admin password set to'

That copy lasts only as long as the container. Every later run of ./setup.sh makes the containers anew, and the line goes with them, so change the password before you update or add a part.

Warning

Nothing else keeps the admin password, and EiN sends no e-mail, so there is no "forgot password". Keep the new one in a password manager. If it is lost, only someone who can act as the administrator can set a new one. Step 5 shows how to give a second person that right.

Check the dashboard

Choose Dashboard under System in the sidebar. Only administrators have it. The page, System dashboard, shows one word above its title for how things stand:

Badge What it means What to do
Healthy Nothing is waiting to be done. Nothing.
Catching up Work is waiting, and some was done in the last hour, as after an import. Wait. It turns to Healthy when the work is done.
Stuck Work is waiting, and none was done in the last hour. Look at the Work tab, and read Health and the dashboard.
Needs a person A check failed. Read the failed check on the Overview tab, and see Troubleshooting.

For the first minute after EiN starts, the dashboard may show warming up while it takes its first readings.

Below the badges, the Overview tab lists every check that is not fine. Warnings do not stop Healthy, and two are expected on an install without the optional parts:

  • with the archive but without the media service, ems says http://ems:8181 is not answering; work that needs it waits;
  • with the assistant but without a language model, llm says http://llm:8190 is not answering; the chat cannot answer until it does.

With the parts installed, the same warnings show for a while after a start, as the media service loads its models and the language model downloads its own the first time; they clear by themselves. Step 3 says how to add either part.

Install the modules you want

What EiN is for comes from its modules. Without any, the sidebar holds only Home, Search and the pages under System. These modules are published:

Module What it adds What it needs
archive Media, Staging, Year, Map, Albums, People, Locations and Devices in the sidebar, and Import media in the Create menu the ems module, installed with it, and the media service
assistant Chat, in the sidebar and as a top-bar button a language model, your own or a hosted one
ems the client for the media service, and the Media service tab on the dashboard the media service

If you installed with the Archive command from einhq.eu, the three are installed already. Open Settings → Modules, choose each module, and check that its panel says Active, not Not set up or Setup failed.

To install a module:

  1. Open Settings → Modules.
  2. Choose the Published modules button beside the filter.
  3. Choose Install beside the module. EiN installs the modules it needs as well, and says so: "Installed, with ems".
  4. Reload the page to see the module's pages.

In EiN's terminal, mod install does the same:

# in EiN's terminal
mod install archive

The archive's photos, videos and recordings need the media service, a separate container that reads dates and places, makes the previews, and finds faces, text and speech. Installing the module does not install the service. If you left it out at the install, add it on the machine:

# on the machine EiN runs on
~/ein/setup.sh --ems

It builds the media service's image, about 30 GB, on the machine, and starts EiN again. Without it, uploads arrive but wait in staging as being prepared. The assistant needs a language model the same way: ~/ein/setup.sh --llm runs one on this machine, and a hosted provider is set in ~/ein/.env. Modules, The media service and The language model have the details.

Decide who sees what

Open Settings → Permissions. Its four cards each say in a sentence what their settings come to.

Visitors. Visitors may browse is Off on a new install, and the setting itself advises keeping it off for a family's own archive. Off, anyone who has not signed in is asked to sign in. A share link still opens what it was made for (step 7). Turn it on only for an archive meant to be public. The setting is CFG_GUEST_BROWSING.

Sharing sets what anything created as shared starts with: an album made with Create → Album, and a group filed from staging into a new album. Its rows:

Row New install What it decides
Owner empty: whoever creates it who owns a new album
Group Users, which is everyone with an account the group a new album is shared with
Permissions Owner Edit, Group “users” View, Everyone else None (as 0750) what the owner, the group and anyone else may do with it

So on a new install the card reads: "Shared with Users: the owner can change it, members can see it, anyone else can't see it." Some common choices:

You want Set
Everyone with an account sees every album, and only its owner changes it nothing: the defaults do this
The family adds to and changes each other's albums Group “users” to Edit
Some accounts are not family, such as friends you share a single album with a family group as Group (see step 5), with Everyone else at None

Each row is saved on its own with Save change. A change applies to what is created afterwards; albums that exist keep their sharing, which you change with Share (step 7). Each person can also narrow what they create, under Profile → Preferences → How widely what you create is shared.

Sign-in sessions. A browser stays signed in for 1 day after its last visit (Browser sign-in), and a session unused for 12 hours ends (Idle session). Lengthen both if the family should stay signed in longer on their own devices.

Sharing and Permissions in depth explain what each choice does.

Create accounts for the family

Give each person an account of their own. What they upload waits in their own staging area, which only they see, until they file it into an album.

  1. Open Settings → Users and choose the New user button beside the filter.
  2. Type the person's Name, such as Helen Okafor. Username is suggested from it (helen). It is lower case and cannot be changed later.
  3. E-mail is optional: with one, they can sign in with it instead of the username. EiN sends no e-mail to it.
  4. Type a Password and Repeat it. You can leave both empty and set the password later, but they cannot sign in until you do.
  5. Under Groups, Users is ticked and greyed: everyone who signs in belongs to it. Tick any other group the person should be in.
  6. Choose Create user. EiN says "Created helen." and opens the account.

If everyone with an account is family, the Users group already covers them, and you need no other group. If some accounts are not family, make a group for the family:

  1. Open Settings → Groups and choose the New group button beside the filter.
  2. Type a Name, such as family (it cannot be changed later), a Title, such as Family, and tick the Members.
  3. Choose Create group.
  4. On Settings → Permissions, choose the group as Group on the Sharing card, and add it under Groups on the New users card, so the New user form ticks it for each new account.

Group changes reach a person the next time they sign in.

Tip

Tick Administrators on request for a second person you trust, or for an everyday account of your own. They can then choose Administer… in the account menu and enter their own password again to act as the administrator, until they sign out or choose Leave admin mode. Such a person can also set a new admin password if it is lost. Ticking Administrators does not do this: it is only the administrator account's own group.

When someone forgets their password, open their account in Settings → Users, type a New password and Repeat it under Password, and choose Set password. Accounts and groups covers the rest: disabling and deleting accounts, groups, and the commands.

Import the first photos

Everything you import lands in your own staging area first, outside the shared library. There EiN reads each file and suggests albums for it, and you decide where it goes.

  1. In the top bar, open Create (the plus) and choose Import media.
  2. Under Into which category?, choose Inbox, or New category for one source kept together. For a new category, choose What it holds, such as Scans for a box of scanned prints or Google Photos export, and type what it is Called.
  3. Click Choose files or Choose a folder, and pick what to upload.
  4. Click Upload.

The category's page opens on its Files tab, and the strip above the tabs shows how far the files are: "N of M arriving", "N being prepared", "N being grouped". The upload runs in the browser tab, so keep the tab open until the Uploads button in the top bar says it is done. Meanwhile the dashboard reads Catching up. For more than about 10,000 files, copy them over SFTP into the category's folder instead, such as /home/admin/staging/files/inbox/; see SSH and SFTP.

A few minutes after the files are prepared, suggested albums appear on the Sort tab. To file one:

  1. Open Staging in the sidebar, then the category, then Sort.
  2. Each group shows its proposal, such as New album “…” or Add to “…”, which Enter accepts on a computer. Where there is none, choose New album… in the group's ⋯ menu, or press N.
  3. In the New album dialog, check the Name and choose Create album. The photos leave staging for the new album, shared as the Sharing card says.

The album is now under Albums in the sidebar. Every decision can be undone, from the message it leaves or from the Done tab. Getting your photos in and Sorting in staging go through every way in and every choice on the Sort tab.

Share an album

With the defaults, an album you file is already visible to everyone with an account. Use Share to change that for one album, or to send a link to someone who has no account.

  1. Open Albums in the sidebar, then the album, and choose Share in its header.
  2. Under Who can see it, Default lets everyone with an account see it, and Private only its owner.
  3. Under People with access, find someone in Add people or groups, then choose Can view or Can edit on their row, or Remove access.
  4. Choose Save.

For someone without an account, choose Create link under Share with a link. Click the address to copy it. The link stops working after 30 days unless you choose another time under Works for, from 1 day to No end date, and Delete link turns it off at once. A link is made and changed straight away, without Save. Whoever opens it sees that album without signing in. Sharing has the rest, including keeping some photos of a shared album private.

Let the family sign in

Give each person:

  • the address you opened in step 1, such as http://ein.local:8080/, or the machine's IP address if their device cannot find the name;
  • their username, or the e-mail address you gave the account, and their password.

They sign in on the sign-in page with Username or e-mail, Password and Sign in. Ask them to change their password at once, under Profile → Security. Finding your way around and Getting your photos in are good pages to send them.

EiN answers on your home network. Reaching it from elsewhere takes an HTTPS proxy of your own in front of it; Ports, HTTPS and remote access explains what EiN needs from one.

On a phone, EiN runs in the browser; there is no app to install from a store. The page fits the screen: the EiN mark at the top left opens the menu. From the browser's menu, a phone can add EiN to its home screen, where it opens full screen, like an app, when EiN is served over HTTPS. EiN does not work offline. EiN on a phone shows what differs.

Keep EiN running

Look at the dashboard now and then. EiN sends no alerts, by e-mail or otherwise: what goes wrong shows on the dashboard and in the logs. Its Storage card shows how much room each part of the data folder has left, and says "full in ~N days" in red when a part fills within two weeks. EiN does not stop work for you when the disk fills.

Update by running the installer again:

# on the machine EiN runs on
curl -fsSL https://einhq.eu/install.sh | bash

It updates ~/ein, then fetches the newest code of EiN and its services, builds it and starts it again, keeping your options in ~/ein/.env, your data and the installed modules. ~/ein/setup.sh alone does the same but leaves the files in ~/ein as they are. There are no releases: an update takes the newest code, and there is no going back to the previous one. Modules are updated separately, with Update in Settings → Modules → Published modules. Updating explains what an update touches.

After the machine restarts, check that EiN came back. Nothing the installer sets up starts it when the machine boots: Docker starts the containers again by itself, but under rootless podman you may have to start EiN yourself:

# on the machine EiN runs on, in ~/ein
podman compose ps
podman compose up -d

Back up. EiN has no backup command; you copy its data yourself, with your own tools. A backup needs three things, taken together:

  • ~/ein/.env, which holds your options and the passwords made at the install, and nothing else keeps them;
  • the data folder, ~/ein/data unless you chose another at the install, and above all its files folder, which holds your originals;
  • the database, which is the container engine's volume ein_db, not part of the data folder.

Note

The database holds every name, album, person and setting, and the files folder holds the files themselves, stored by an id rather than by name. Neither is any use without the other, so copy them at the same time, and back up before each update.

Your data: backup, moving and removing gives a procedure, and Troubleshooting helps when something goes differently.
